# Close out (Step 9)

Runs once Step 8's verify call is clean, so every link written here uses the archived path. Three parts, each asked per [para-shared/asking.md](../../para-shared/asking.md) with a skip that writes nothing. In `preview`, each is proposed with the destination the move would produce.

## The Track record line

For a project or an area; an idea never happened, so it gets none.

One question: a line for the root `README.md`'s `## Track record` saying what was delivered, for whom, and the result, linking the archived brief (or the README it archived as).

- **Match the section's own shape**: a dated bullet, a paragraph per engagement, a table row. Where it groups work by theme or counts it, propose extending the matching line rather than adding one. A line already naming this entity (an `inbound.references` hit in `README.md`, repointed in Step 7) is updated, never doubled.
- **Recommend Skip for a routine closure** no line covers: a ticket, a small fix, one of many of its kind. Recommend the line for work a reader of the README should know was done.
- **History only.** The line says what was done, never what is still open or next, so the vault's rule against work state in `README.md` holds.
- **Figures follow the vault's `.claude/rules/figures.md`.** The line links the brief rather than copying a number out of it; a figure appears in it only where `README.md` is that figure's one home, or as a copy carrying its as-of date and its reason.
- **A README with no `## Track record`** gets the heading proposed with the line, where the vault's `CLAUDE.md` places it.

## Lessons

Ask what to do differently next time, starting from whatever the brief already records (a lessons, retrospective or post-mortem section). Route at most three, one question each, to a home something still reads:

- **A playbook in `resources/`**: the one already covering that kind of work, or a new one in the folder of its kind.
- **A rule in the vault's `CLAUDE.md`**, for one every future run of that kind must follow.
- **A line in `.claude/rules/working-preferences.md`**, for how the operator wants the agent to work, added and dated under that file's own rules.
- **Leave it in the closed brief**, the option that changes nothing.

A routed lesson is written in its home's own form: a playbook step, a rule, a dated preference line. Any lesson beyond the three stays in the brief.

## A won deal: the client's words

Only where `lifecycle.won` is true (by hand: the Stage line names the first stage in its lifecycle table whose home sits under `projects/`, or the brief carries a dated `Won` line), and the vault does not already hold this client's words on this work.

Ask for the outcome in the client's own words from a file on record, offering any passage the archived `sources/` hold (a mail, a transcript, a review). Record it:

- **Verbatim**, in quotation marks and its original language, attributed by name and role.
- **Linked to its source file.**
- **With its clearance**: `named`, `anonymised` or `internal only`. Default it to the vault's own rule on public outputs where its `CLAUDE.md` states one; otherwise ask it as a question of fact, no option recommended. A public output uses only `named` and `anonymised` lines.

It goes wherever the vault already keeps clients' words. With no such place, propose a `## What clients said` section in `README.md`, after the four fixed headings.

## The report

Step 8's report adds: the Track record line written, extended or skipped; each lesson and where it went; every lesson left in the closed brief, saying plainly that nothing reads it there; and for a won deal, the words recorded with their clearance, or that none was on file.

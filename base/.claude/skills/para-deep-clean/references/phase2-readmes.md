# Phase 2 - README structure

## Step 2.0 - Root README first

Fix Phase 1's shape findings against the four headings the vault's `CLAUDE.md` fixes, facts verbatim: rename or translate headings to the four; fold other opening sections under them (an inventory or brand list becomes a `###` under Track record); write Vision from what the vault already says, flagged as inferred; reduce a "Working in this vault" section to one closing line.

## Step 2.1 - The declared shape

Find the shape for entity READMEs and briefs, per [A vault's rule files](../../para-shared/operating-discipline.md#a-vaults-rule-files). This skill brings no section list of its own.

- **Declared:** audit against it and add nothing; propose extending it where it lives if it is genuinely incomplete. Audit an order only where the shape fixes one. "At least" names facts, not headings: the facts must be present under any heading, and renaming to the shape's headings is offered, never applied.
- **None:** draft a shape file from what the existing READMEs share, per [rule-files.md](../../para-shared/rule-files.md), with `_n/a_` lines for sections that do not apply, and propose it with its pointer. Whether it fixes an order is the operator's call.

## Step 2.2 - Archived entities

Use the archived-entity shape `CLAUDE.md` or its rule files document; with none, ask. An archived entity needs no open-items or relationship sections, only its status marker, why it was archived and where its sources live.

## Step 2.3 - Apply

Do the first README as a worked example and pause for approval before batching the rest. Facts stay verbatim, per [Preserve, don't rewrite](../../para-shared/operating-discipline.md#preserve-dont-rewrite). Promote inline bold blocks (Ownership, Notary) to `##` sections unless the shape uses bold labels there, and add `_n/a_` for sections that do not apply. Where a status or cost-basis table makes no sense for the entity type, put one domain-appropriate table near the top that answers "where do we stand" in one look.

In a vault with no entity README tier, apply to each brief only what its shape file names and to each contact file only what `CLAUDE.md` fixes: no promoted bold blocks and no `_n/a_` lines the shape does not require.

## Changelog

**Integrations.** New: `vault-mirror` at 2026.10.01, git history for a vault on a synced drive, kept in a repository outside the drive. `mirror.py`, installed at `resources/scripts/vault-mirror/mirror.py`, copies the vault one way into the mirror named by `PARAOS_VAULT_MIRROR` or `--mirror` and commits, refusing a mirror with uncommitted edits unless `--force`. It copies every file but the ones no script can read (Drive's native-format pointers, OneDrive's root marker, Office lock files), and the mirror's own `.git/info/exclude` decides what the history keeps; the integration ships a starting one. Reaction: none for a vault that keeps its own `.git`. A vault on a synced drive may adopt it through the integration's README, which also moves a vault that already holds `.git` onto a mirror.

## What changes for you

A vault on Google Drive, OneDrive or SharePoint can now have a full git history without keeping git's files inside the drive, where they break: a new optional script copies the vault into a repository on your own disk and records a change each time you run it.

## Do you need to do anything?

Only if you want that history for a vault on a synced drive: the upgrade does not set it up, and the vault mirror's own instructions walk through it.

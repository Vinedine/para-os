## Changelog

- If the machine has a vault registry (`$PARAOS_HOME/vaults.json`) and the multi-vault skills are installed: copy `multi-vault/para-command-center/` from the para-os clone beside them, then run the shared library's `paraos_pages.py retire --page global-brief --replaced-by command-center` and `paraos_pages.py retire --page funnel --replaced-by command-center`, each only where the pages index lists that page, and say the two old artifacts are the operator's to delete: `$PARAOS_HOME/cache/pages.json`
- If the machine has a vault registry: ask, vault by vault, which `neighbourhood` it stands in on the Command Center and, where the operator groups vaults by theme, its `street`, and write each answer into that vault's registry entry; an operator who declines keeps the default groups: `$PARAOS_HOME/vaults.json`
- If the task registry names `"skill": "para-global-brief"`: propose changing that entry's skill to `para-command-center`, and say the scheduled task's own prompt needs the same change, which only the operator can make: `$PARAOS_HOME/tasks.json`
Retired: `.claude/skills/para-global-brief/`

## Also new

- **One page shows every vault at once.** The Command Center draws each vault as a building in a neighbourhood you name, with its health grade, what waits in its triage folder and what is held for you; what came in over the week, grouped by kind, and where it went; the scheduled runs, the repos and the websites; and the weeks ahead. A script builds it from your files, with no judgment from the model, so the same files always give the same page. It replaces the global brief and the triage funnel page, which are retired. A script nobody listed is still seen: the connections registry now reads the code of the scripts in each vault, and of the ones your own skills run from a code repo, and counts any that calls an outside host or a command-line tool you listed, so the page draws it under the system it reaches and `/para-audit` names it until it has an entry.

## What to do

- If you run several vaults: point your morning scheduled task at `/para-command-center` instead of `/para-global-brief`, and take the funnel page step out of your ingest task's prompt.
- If you run several vaults: delete the old All Vaults and Triage funnel artifacts once the Command Center is published.
- If a vault you set up is no longer read, such as one handed over to a client, and you want it on the page: list it in `past-vaults.json` in your para-os folder, from the template beside the multi-vault README.
- If `/para-audit` or the Command Center names a script as not in the connections registry: give it an entry in `connections.json` in your para-os folder, or add its path to the `ignore` list there when it is not a connection, such as a sign-in helper.

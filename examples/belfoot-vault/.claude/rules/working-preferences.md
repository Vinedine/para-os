# Working preferences

How the operator likes to work with the agent: the one thing built-in memory is good at, kept in the vault instead, where it is read, versioned and reverted like everything else. A convention, not a document shape: it governs every answer, draft and report in this vault. It is scoped to `**` so it loads with the first file a session reads; read it explicitly before drafting anything for the operator.

## What belongs here

**How, never what.** A preference says how the operator wants the work done: tone and register, length, format, which details to lead with or leave out, how to ask, when to stop and check. One line each.

- **In:** "Lead with the answer, reasons after." "No tables in anything I forward to a client." "Ask before touching anything under `areas/business/`."
- **Out:** a fact about a project, a person or a figure belongs in the file it describes (`## Memory` in `CLAUDE.md`). A rule every vault of this kind needs belongs in `CLAUDE.md`. A preference user-level instructions already carry is repeated here only if it must travel with the vault: another machine, agent or team. How someone writes (greeting, sign-off, phrasing) goes to their voice profile where they have one, under its own rules in `para-shared/voice-profile.md`.

## How it changes

**Only with the operator's approval.** The agent never writes to this file on its own reading of what the operator wants.

- **Propose on repetition.** When the operator corrects the same thing a second time, propose the preference as one line, quoting the correction, and add it only on a yes.
- **An explicit ask is the approval.** "Remember that I want..." is a yes; add it and say where.
- **Date each line** with the day it was added, `_(YYYY-MM-DD)_` at its end, so a stale preference can be recognised and questioned.
- **A contradiction replaces, never stacks.** A new preference that conflicts with an old one replaces it, after the operator confirms which one holds.
